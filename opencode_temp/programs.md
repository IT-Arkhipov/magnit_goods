# Программы исполнителя: 2025 → 25

> Условие: команды A (−1), B (⌊x/3⌋), C (⌊x/4⌋).
> Найти количество программ, преобразующих **2025** в **25**, траектория которых
> **содержит 250**, но **не содержит 42**.
> Требование: стек не должен переполняться → решение итеративное.

## 1. Ключевые наблюдения

### 1.1. Все команды неубывают по модулю — то есть только уменьшают число

| Команда | Эффект | Условие применимости |
|:------:|:------|:---------------------|
| A | `x → x − 1` | всегда (для `x > 0`) |
| B | `x → ⌊x/3⌋` | всегда |
| C | `x → ⌊x/4⌋` | всегда |

Каждая команда переводит число в **меньшее или равное** исходному (строго меньшее при `x ≥ 1`).
Значит, граф вычислений — **ациклический, направленный от больших чисел к меньшим**.
Это автоматически снимает проблему переполнения стека: можно считать «снизу вверх»
от цели `25` к старту `2025`, не используя рекурсию.

### 1.2. Траектория — обыкновенный путь в графе

«Траектория вычислений» — это последовательность значений:
`x₀ = 2025, x₁, x₂, …, xₖ = 25`, где каждый шаг получен одной из команд A/B/C.
Каждой такой последовательности соответствует **ровно одна программа**
(набор команд зависит только от пары `(xᵢ, xᵢ₊₁)`).

Значит, **количество программ = количеству путей** в графе из `2025` в `25`,
проходящих через `250` и не проходящих через `42`.

## 2. Сведение к двум DP

Традиционный приём «вычесть плохое из общего»:

- **`f[v]`** — количество путей из `v` в `25`, **не заходящих в `42`**.
- **`g[v]`** — количество путей из `v` в `25`, **не заходящих в `42` и не заходящих в `250`**.

Тогда искомое количество = «пути, не заходящие в 42» минус «пути, не заходящие ни в 42, ни в 250»
= `f[2025] − g[2025]`.

Геометрически: `g` отсекает все пути, проходящие через `250`. Оставшиеся после вычитания
программы — это в точности те, которые `250` посещают (а `42` — нет).

## 3. Рекуррентные формулы

Для `v > 25` и `v ≠ 42`:

```
f[v] = f[v − 1]  +  f[⌊v/3⌋]  +  f[⌊v/4⌋]
g[v] = g[v − 1]  +  g[⌊v/3⌋]  +  g[⌊v/4⌋]      (при v ≠ 250)
g[250] = 0
```

Граничные условия:

```
f[25] = 1           # пустая программа — мы уже в цели
g[25] = 1
f[42] = 0           # запрет
g[42] = 0
g[250] = 0          # запрет для «g»
```

Слагаемые, ссылающиеся на числа `< 25`, игнорируются:
из `v < 25` попасть в `25` нельзя (команды только уменьшают), поэтому вес таких вершин равен 0.

## 4. Почему итеративно, а не рекурсивно

- a) Граф ацикличен (числа строго убывают), потому **естественный порядок снизу вверх**:
  считаем `v` от `25` до `2025`. К моменту обработки `v` все `v' < v` уже посчитаны.
- б) Размер массивов `O(start − target) = 2000`, время `O(start)` — мгновенно.
- в) **Никакой рекурсии → никакого переполнения стека**, что и требовалось в условии.

## 5. Код (DP снизу вверх)

```python
def solve(start, target, must_contain, forbidden):
    N = start
    f = [0] * (N + 1)  # пути, избегающие forbidden (42)
    g = [0] * (N + 1)  # пути, избегающие forbidden (42) И must_contain (250)
    f[target] = 1
    g[target] = 1

    for v in range(target + 1, N + 1):
        if v == forbidden:
            continue  # остаётся 0
        children = (v - 1, v // 3, v // 4)
        for c in children:
            if c == forbidden or c < target:
                continue
            f[v] += f[c]
        if v == must_contain:
            g[v] = 0  # траектория, проходящая 250, исключается в g
            continue
        for c in children:
            if c == forbidden or c == must_contain or c < target:
                continue
            g[v] += g[c]

    return f[start] - g[start]


if __name__ == "__main__":
    print(solve(start=2025, target=25, must_contain=250, forbidden=42))
    # 564235
```

## 6. Двойная проверка через декомпозицию

Любую программу `2025 → 25`, проходящую через `250`, можно **единственным образом**
разрезать в точке первого достижения `250`:

- участок **`2025 → 250`**: не заходит в `42`, не заходит в `250` до конца;
- участок **`250 → 25`**: не заходит в `42` (в `250` повторно попадать не нужно).

Число таких «склеек» = `paths(2025→250, без 42, без промежуточного 250) × paths(250→25, без 42)`.

Заметим, что условие «без промежуточного 250» в первой части избыточно: наличие `250`
в пути `2025 → 250` обязательно **без** повторного появления `250` как промежуточной
вершины (повтор может быть только в конце). Поскольку команды строго убывают, `250`
между `2025` и `250` появиться не может. Поэтому достаточно считать просто `paths(2025→250, без 42)`.

```python
def paths(src, dst, forbid):
    f = [0] * (max(src, dst) + 1)
    f[dst] = 1
    for v in range(dst + 1, src + 1):
        if v == forbid:
            continue
        for c in (v - 1, v // 3, v // 4):
            if c == forbid or c < dst:
                continue
            f[v] += f[c]
    return f[src]


print(paths(2025, 250, 42) * paths(250, 25, 42))  # 564235
```

Оба метода дают **564235** — ответы совпали.

## 7. Ответ

```
Количество программ = 564 235
```

## 8. Сводка приёмов, полезных для аналогичных задач

| Приём | Где применили |
|------|----------------|
| Все команды уменьшают число → граф ацикличен, порядок снизу вверх | Итеративное ДП без рекурсии |
| «Запрет вершин» | Обнуляем `f[42]`/`g[42]` (в `g` ещё и `g[250]=0`) |
| «Обязательное прохождение вершины» | `Ответ = f − g`, где `g` дополнительно запрещает `250` |
| Альтернатива: разрезание пути в первой вершине достижения | Деклозиция `paths(2025→250) × paths(250→25)` |
| Игнорирование вершин `< target` | Они не дают вклада: из них нельзя расти обратно |
