# Spec Delta

## MODIFIED Requirements

### Requirement: Конфигурация загружается из .env при старте
При старте сервер SHALL загружать переменные из файла `.env` в корне репозитория. Переменные, уже заданные в окружении процесса, SHALL иметь приоритет над значениями из `.env`. Планировщик SHALL запускаться при каждом старте независимо от `STORE_CODE`.

#### Scenario: Магазин задан только в .env
- **WHEN** `.env` содержит `STORE_CODE=992104`, а в окружении процесса переменная не задана, и сервер запускается
- **THEN** `STORE_CODE` в окружении процесса равен `992104`

#### Scenario: Переменная окружения имеет приоритет
- **WHEN** `STORE_CODE` задан и в окружении процесса, и в `.env` с разными значениями
- **THEN** используется значение из окружения процесса

#### Scenario: Старт без магазина
- **WHEN** сервер запускается без `STORE_CODE`
- **THEN** планировщик запущен с заданиями `scan_all_stores` и `update_catalog`

### Requirement: Смена магазина применяется без перезапуска
Успешный `POST /api/stores/select` с `update_env=true` SHALL, помимо записи в `.env`, обновить `STORE_CODE` и `STORE_TYPE` в окружении работающего процесса. Выбранный магазин SHALL использоваться как источник каталога при следующей полной замене каталога; задания планировщика от выбора не зависят.

#### Scenario: Смена магазина
- **WHEN** клиент выбирает магазин B через `POST /api/stores/select`
- **THEN** следующая полная замена каталога запрашивает категории для магазина B без перезапуска сервера

#### Scenario: Первый выбор магазина
- **WHEN** сервер запущен без `STORE_CODE`, и клиент выбирает магазин через `POST /api/stores/select`
- **THEN** `STORE_CODE` в окружении процесса равен коду выбранного магазина, задания планировщика не меняются

## ADDED Requirements

### Requirement: Планировщик сканирует все активные магазины
Ежедневное задание планировщика SHALL сканировать все активные магазины по отслеживаемым категориям так же, как `POST /api/catalog/scan-all-stores` (задание типа `scan_all_stores`), и SHALL пропускаться, если такое задание уже выполняется. Еженедельное задание SHALL выполнять полную замену каталога.

#### Scenario: Скан уже идёт
- **WHEN** в 8:00 есть задание `scan_all_stores` в статусе `running`
- **THEN** планировщик не создаёт второе задание
