# Spec Delta

## Purpose

Определяет, откуда сервер берёт конфигурацию текущего магазина (`STORE_CODE`, `STORE_TYPE`) и как смена магазина через API применяется к работающему процессу и планировщику.

## ADDED Requirements

### Requirement: Конфигурация загружается из .env при старте
При старте сервер SHALL загружать переменные из файла `.env` в корне репозитория до инициализации планировщика. Переменные, уже заданные в окружении процесса, SHALL иметь приоритет над значениями из `.env`.

#### Scenario: Магазин задан только в .env
- **WHEN** `.env` содержит `STORE_CODE=992104`, а в окружении процесса переменная не задана, и сервер запускается
- **THEN** планировщик запускается с заданиями для магазина 992104

#### Scenario: Переменная окружения имеет приоритет
- **WHEN** `STORE_CODE` задан и в окружении процесса, и в `.env` с разными значениями
- **THEN** используется значение из окружения процесса

### Requirement: Смена магазина применяется без перезапуска
Успешный `POST /api/stores/select` с `update_env=true` SHALL, помимо записи в `.env`, обновить `STORE_CODE` и `STORE_TYPE` в окружении работающего процесса и перерегистрировать задания планировщика на выбранный магазин (запустив планировщик, если он не был запущен).

#### Scenario: Смена магазина
- **WHEN** планировщик работает для магазина A, и клиент выбирает магазин B через `POST /api/stores/select`
- **THEN** следующие запуски заданий `update_prices` и `scan_catalog` выполняются для магазина B без перезапуска сервера

#### Scenario: Первый выбор магазина
- **WHEN** сервер запущен без `STORE_CODE`, и клиент выбирает магазин через `POST /api/stores/select`
- **THEN** планировщик запускается с заданиями для выбранного магазина
