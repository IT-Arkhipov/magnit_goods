# Spec Delta

## Purpose

Определяет хранение универсального дерева категорий Магнита (корневые категории и подкатегории) и его полную синхронизацию с API Магнита без потери связей товаров и флагов отслеживания.

## ADDED Requirements

### Requirement: Полная замена каталога сохраняет идентичность категорий
При полной замене каталога категория, `magnit_id` которой присутствует и в БД, и в ответе API, SHALL сохранить свой внутренний идентификатор и флаг `is_tracked`; изменяются только её название и родитель.

#### Scenario: Товары остаются привязанными
- **WHEN** товар привязан к подкатегории с `magnit_id=100`, и полная замена каталога снова получает `magnit_id=100` из API
- **THEN** после замены товар ссылается на ту же категорию, а `GET /api/products?category_ids=<её id>` возвращает этот товар

#### Scenario: Переименование категории
- **WHEN** API вернул для существующего `magnit_id` новое название
- **THEN** у категории обновлено название, внутренний ID и `is_tracked` не изменились

### Requirement: Полная замена каталога добавляет и удаляет категории по разнице
Полная замена каталога SHALL создавать категории, `magnit_id` которых есть в API, но нет в БД, и удалять категории, `magnit_id` которых нет в ответе API. Новые категории SHALL создаваться с `is_tracked=false`.

#### Scenario: Новая подкатегория
- **WHEN** API вернул подкатегорию с `magnit_id`, отсутствующим в БД
- **THEN** она создаётся под соответствующей корневой категорией с `is_tracked=false`

#### Scenario: Исчезнувшая подкатегория
- **WHEN** подкатегория из БД отсутствует в ответе API
- **THEN** она удаляется, а остальные категории не затрагиваются

### Requirement: Ошибка API не изменяет каталог
Если при полной замене каталога не удалось получить данные хотя бы одной корневой категории, система SHALL не изменять таблицу категорий и SHALL сообщить об ошибке в статусе замены.

#### Scenario: Сбой одной корневой категории
- **WHEN** запрос к API для одной из корневых категорий завершился ошибкой
- **THEN** `GET /api/categories/fetch-magnit-ids/status` показывает ошибку, а категории в БД остались прежними
