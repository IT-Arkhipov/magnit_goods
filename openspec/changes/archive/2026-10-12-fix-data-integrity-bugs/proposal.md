# Proposal

## Why

Анализ несоответствий 2026-10-12 выявил ошибки, из-за которых система показывает неверные данные или молча не выполняет заявленные функции: поиск товаров игнорирует фильтр магазина, полная замена каталога ломает привязку товаров к категориям, отменённые задания помечаются как завершённые, `.env` не читается при старте (планировщик не запускается), даты изменения цены «плывут» при каждом скане. Это ядро продукта (мониторинг цен), поэтому чинить нужно в первую очередь.

## What Changes

- **Поиск товаров** (`GET /api/products?search=...`) сохраняет все фильтры обычного списка: магазин, окно видимости устаревших товаров, наличие/остаток, категории, цены.
- **Полная замена каталога** (`POST /api/categories/fetch-magnit-ids`) обновляет категории по `magnit_id` (upsert) вместо удаления и пересоздания таблицы: внутренние ID существующих категорий сохраняются, товары остаются привязанными к своим категориям; удаляются только категории, исчезнувшие из API.
- **Отмена заданий**: задание со статусом `cancelled` больше не перезаписывается в `completed` по окончании фоновой работы (`/api/prices/update`, задания планировщика).
- **Очистка при старте**: зависшие задания в статусе `pending` (а не только `running`) помечаются `failed` при перезапуске сервера.
- **Конфигурация из `.env`**: `.env` загружается при старте приложения; `POST /api/stores/select` применяет новый магазин к работающему процессу (переменные окружения и задания планировщика) без перезапуска.
- **Семантика последнего изменения цены**: `last_change_price` / `last_change_date` / `last_price_change` обновляются только в момент реального изменения цены; `last_change_price` — цена непосредственно до этого изменения, `last_change_date` — дата изменения.
- **Товары без цены**: позиция из API без цены пропускается (с предупреждением в логе) вместо сохранения с ценой 0 и ложным «снижением на 100%».
- **Ошибки валидации**: `DELETE /api/products/clear-by-categories` с некорректным `category_ids` возвращает 400, а не 500.

## Capabilities

### New Capabilities
- `product-catalog`: выдача списка и поиска товаров — фильтры, видимость, наличие, удаление товаров.
- `category-catalog`: хранение дерева категорий и его полная замена из API Магнита с сохранением идентичности категорий.
- `price-tracking`: правила фиксации текущей/предыдущей цены, процента изменения и последнего изменения цены по результатам сканов.
- `scan-jobs`: жизненный цикл фоновых заданий (pending/running/completed/failed/cancelled), отмена и восстановление после перезапуска.
- `runtime-config`: источник конфигурации магазина (`.env`) и применение смены магазина к работающему серверу.

### Modified Capabilities
Нет — в `openspec/specs/` пока нет спецификаций.

## Impact

- `src/server/routes/catalog.py` — `list_products`, `clear_products_by_categories`
- `src/server/services/catalog_updater.py` — `replace_all_categories`
- `src/server/services/catalog_scanner.py` — `scan_products` (признак отмены), `_save_products` (last_change_*, пропуск товаров без цены)
- `src/server/services/magnit_api.py` — `_parse_product`
- `src/server/routes/prices.py`, `src/server/scheduler.py` — финализация статуса задания; вынос `register_jobs`
- `src/server/routes/stores.py` — `select_store`, перенос `_mark_all_running_failed_on_startup`
- `src/server/main.py` — `load_dotenv()` до чтения переменных окружения
- Схема БД не меняется; уже записанные неверные `last_change_date` не исправляются (см. design.md)
- Перекрывает шаг 3.1 из `docs/PLAN_FIXES_2026-09-27.md`
