# Design

## Context

Мотивация — в proposal.md (§ Why). Текущее состояние: `ruff check src/` выдаёт 38 ошибок в 11 модулях; 25 из них (`F401` ×15, `F541` ×10) помечены `[*]` как safe-исправляемые, остальные 13 (`E711` ×3, `E712` ×3, `E722` ×5, `F841` ×2) требуют содержательных решений.

Инспекция кода выявила два факта, определяющих подход:

1. **E711/E712 — ложные срабатывания в SQL-контексте.** Все шесть случаев — выражения SQLAlchemy над колонками, а не сравнения Python-значений:
   - `database.py:344` — `db_session.query(Store).filter(Store.shop_type != None)`
   - `routes/catalog.py:222` — `.filter(Category.parent_id != None)`
   - `routes/catalog.py:593` — `.filter(... Category.parent_id != None)`
   - `routes/catalog.py:237` — `.filter(Category.is_tracked == True).count()`
   - `routes/catalog.py:399` — `case((Product.in_stock == True, 1), else_=0)`
   - `routes/catalog.py:813` — `.filter(Store.is_active == True).first()`

   Для SQL-колонок операторы `==`/`!=` перегружены SQLAlchemy и компилируются в `IS NULL`/`IS NOT NULL` — это единственная идиома построения таких условий (в отличие от `is_(None)`, `==` привычен в проекте). Замена на `is None`/`is not None` вернула бы Python-bool и сломала запрос.

2. **E722 в `store_selector.py` — осмысленная правка.** Все пять `except:` — узкие внутренние блоки в циклах перебора Playwright-элементов (`if btn.is_visible(...): btn.click(); return True` → `except: continue`), каждый из которых уже обёрнут внешним `except Exception`. Здесь проглатываются в том числе `KeyboardInterrupt`/`SystemExit` — замена на `except Exception:` корректна и не меняет поведение для реальных ошибок DOM/таймаутов.

## Goals / Non-Goals

**Goals:**
- `ruff check src/` → 0 сообщений (exit 0), без отключения правил глобально.
- Сохранить SQL-семантику существующих запросов без изменений.
- Каждый класс правок проверяем отдельно (ruff `--select` по классу).

**Non-Goals:**
- Рефакторинг логики `store_selector.py` (типизация перехватываемых исключений глубже `Exception`).
- Настройка/создание `pyproject.toml` или `ruff.toml` (конфигурация ruff вне рамок изменения).
- Изменение стиля `col == None` на `col.is_(None)` во всём проекте.

## Decisions

**1. F401+F541 (25×): `ruff check --select F401,F541 --fix` вместо ручных правок.**
Ruff помечает ровно эти 25 как safe-фиксы; safe-режим не трогает `E711`/`E712`/`E722`/`F841` и не применяет unsafe-преобразования. Ограничение селектором по классам исключает риск задеть чужие изменения в рабочем дереве (в diff уже есть незакоммиченные правки `main.py`, `scheduler.py` и др.). Альтернатива — ручные 25 правок: тот же результат, но дороже и без гарантии идентичности фиксов. После фикса — выборочная проверка `git diff`, что удалены только импорты/префиксы `f`.

**2. E711/E712 (6×): построчный `# noqa: E711` / `# noqa: E712` вместо изменения выражений.**
Выражения не трогаем (см. Context, п.1). Альтернативы:
- глобальное отключение `E711`/`E712` в конфиге ruff — отвергнуто: заглушит настоящие `if x == None:` вне SQLAlchemy;
- перевод на `.is_(None)` / `.is_(True)` — семантически эквивалентно, но меняет 6 SQL-выражений ради стиля и расходится с принятым в проекте стилем (в `catalog.py:591` уже стоит `# noqa: E712` — конвенция проекта уже выбрана в пользу noqa);
- `filter(Category.is_tracked)` без сравнения — работает в `filter()`, но не в `case(...)` (строка 399) и менее явно.
Выбран вариант, уже используемый в проекте; в `case((Product.in_stock == True, 1), ...)` noqa ставится на ту же строку.

**3. E722 (5×): `except:` → `except Exception:`.**
Сохраняет проглатывание ошибок перебора элементов (текущее поведение) и перестаёт глушить системные исключения. Альтернатива — конкретные `TimeoutError`/`PlaywrightTimeoutError`: точнее, но требует импорта и аудита всех путей; выходит за рамки lint-фикса.

**4. F841 (2×): удалить присваивания.**
`catalog_scanner.py:603` — удалить строку `yesterday = today - timedelta(days=1)` (переменная `today` используется ниже, `yesterday` — нет). `magnit_api.py:240` — удалить строку `product_name = item.get("name") or item.get("title", "")` (ruff подтверждает отсутствие использований в области видимости). Альтернатива (`_ = ...`) скрывает мёртвый код вместо его удаления.

**5. Коммиты — по классам правил, не один общий.**
Порядок: F401+F541 (автофикс) → F841 → E722 → E711/E712 (noqa). Каждый коммит реверсивен независимо; при регрессе в SQL-запросе откачивается только последний коммит. Альтернатива (один коммит) дешевле, но связывает механические и содержательные правки.

## Risks / Trade-offs

- [`ruff --fix` затронет строки, которых нет в 38 сообщениях] → фикс запускается с `--select F401,F541`, до фикса — `git stash`/проверка чистоты целевых файлов; после — `git diff` и `ruff check` целиком.
- [noqa замаскирует будущие настоящие `== None` на тех же строках] → noqa точечный (построчный) с указанием кода правила; строки и так SQL-выражения, их смысл не изменится.
- [`except Exception` в `store_selector.py` проглотит ошибку, которую `except:` ловил иначе] → поведение для всех подклассов `Exception` идентично; изменится только реакция на `BaseException` (KeyboardInterrupt), что и есть цель.
- [Удаление `product_name` скрывает намерение использовать имя товара] → в `magnit_api.py` имя берётся из других полей в месте формирования словаря товара; мёртвое присваивание не воспроизводит функциональность.
- [Расхождение нумерации строк задач с фактической из-за сдвигов после автофикса] → задачи формулируются по содержимому строки (правило + файл + имя), а не по номеру; номера сверяются выводом `ruff check --output-format=concise`.

## Migration Plan

Миграция не требуется: изменения не затрагивают данные, API и контракты. Деплой — обычные коммиты по классам. Rollback — `git revert` соответствующего коммита.
