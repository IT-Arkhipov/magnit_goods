# Proposal

## Why

Страница `/products` уже грузит и склеивает все выбранные магазины (`loadProductsEnhanced`, products.html:2658), но при склейке запись товара отбирается по первому магазину из выбранных (обычно 992104): `if (!productMap[p.product_id])` (products.html:1987). Фильтр режима «Новая цена» проверяет `price_change_percent` именно этой склеенной записи (products.html:2171), а счётчики статистики берутся только по первому магазину (products.html:1852). Поэтому снижение −25%, зафиксированное в 210117, не даёт строке пройти фильтр, хотя в колонке 210117 для этого же товара отображается 119.99 ↓25% — пользователь не видит товар в списке снижений.

## What Changes

- Правило склейки записей товара: вместо «запись первого магазина побеждает» — предпочтение записи со снижением (`price_change_percent > 0`), при нескольких снижениях — с наибольшим процентом; если снижений нет/недоступно наличие — прежнее поведение (запись в наличии по порядку выбранных магазинов, затем первая по порядку). При фильтре «Нет в наличии» ступени зеркальны: предпочитается запись без наличия (со снижением — с наибольшим процентом), чтобы товар, отсутствующий хотя бы в одном выбранном магазине, не пропадал из фильтра.
- Режим «Новая цена» показывает товар, если снижение есть у него в любом выбранном магазине и в этом магазине товар в наличии. Скидки на товары без наличия в магазине-источнике по-прежнему не показываются (кроме фильтра «Нет в наличии», где отсутствующие товары показываются намеренно).
- `GET /api/products/stats` принимает набор магазинов; счётчики на странице (всего / в наличии / со снижением / с повышением) считаются по объединению выбранных магазинов. Все счётчики — по уникальным `product_id` (в т.ч. для одного магазина и вызова без магазина); «Со снижением» учитывает только снижения на товарах в наличии — как список режима «Новая цена».
- Колонки выбранных магазинов, цены и проценты в них, сравнение и экономия — без изменений.
- Одиночный `store_code`, контракт полей ответа и существующие сценарии `product-catalog` сохраняются. Меняются значения статистики: `with_price_decrease` одиночного магазина может уменьшиться (снижения на отсутствующих товарах не считаются), `total` без магазина считает уникальные товары, а не строки — фиксируется в `docs/API.md`.

## Capabilities

### New Capabilities

_(нет)_

### Modified Capabilities

- `product-catalog`: уточнить поведение склейки товаров выбранных магазинов — атрибуция записи и видимость снижений в режиме «Новая цена» — и добавить требование о статистике по набору магазинов.

## Impact

- Код: `src/server/templates/products.html` (`loadProductsEnhanced` — слияние записей, `renderProductsList` — фильтр режима «Новая цена», `loadProductStats` — запрос статистики), `src/server/routes/catalog.py` (`get_products_stats`), `src/server/services/product_query.py` (счётчики по набору магазинов), `src/server/schemas.py` (необязательный параметр статистики, если нужен отдельный тип).
- API: расширение `GET /api/products/stats` набором магазинов; `GET /api/products` и `GET /api/products/multi-prices` не меняются.
- Документация (обязательно в том же изменении): `docs/API.md`, `docs/USER_GUIDE.md`.
- БД/миграции: не требуются — данные уже хранятся по `store_code`.
- Зависимость: изменение опирается на незакоммиченный код архивированного `hide-zero-stock-prices` в `products.html` (`hasStock`, проверки остатка) и синхронизированную основную спецификацию; их нужно закоммитить до реализации.
