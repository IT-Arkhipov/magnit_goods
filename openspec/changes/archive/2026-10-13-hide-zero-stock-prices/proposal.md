# Proposal

## Why

Список товаров и статистика уже скрывают товары с нулевым остатком: `build_product_query()` по умолчанию отбрасывает `in_stock=false` и `quantity=0`, `get_products_stats()` считает наличие по тому же правилу. Но в режиме сравнения цен по магазинам на `/products` цены других магазинов приходят из `GET /api/products/multi-prices`, который возвращает все строки без учёта остатка. В результате в ячейке магазина показывается цена товара, которого там нет, тултип подписывает такой остаток как «в наличии», а неактуальная цена участвует в выборе минимальной цены и расчёте экономии.

## What Changes

- В таблице сравнения по магазинам цена магазина, где у товара `in_stock=false` или `quantity` не больше 0, не показывается: ячейка выводится как «-», как для магазина без товара.
- Такие цены не участвуют в расчёте минимальной цены, подсветке, проценте экономии и фильтре «экономия ≥ N%».
- Тултип ячейки цены больше не подменяет нулевой остаток подписью «в наличии».
- Исключение: при фильтре наличия «Нет в наличии» (страница явно запрашивает отсутствующие товары) цены с нулевым остатком показываются.
- API не меняется: `multi-prices` по-прежнему отдаёт все строки, потому что на них опирается проверка наличия в списке покупок (`base.html:validateShoppingList`).

## Capabilities

### New Capabilities

- *нет*

### Modified Capabilities

- `product-catalog`: добавляется требование к сравнению цен по магазинам на странице товаров. Правило наличия для списка и статистики уже действует и не меняется.

## Impact

- `src/server/templates/products.html`: режим сравнения (`renderProductsList(products, selectedStores, allStorePrices, …)`, `renderSimpleList`), фильтр по проценту экономии.
- Бэкенд (`product_query.py`, `routes/catalog.py`), схема БД и контракт API не меняются.
