# Spec Delta

## Purpose

Определяет, как сервер при старте применяет миграции схемы SQLite и ведёт их учёт, чтобы каждая миграция была применена полностью ровно один раз, а частичные сбои не фиксировались как успех.

## ADDED Requirements

### Requirement: Миграция регистрируется только при успехе
Миграция SHALL записываться в реестр выполненных миграций только после успешного выполнения. Если миграция завершилась ошибкой, сервер SHALL записать предупреждение в лог, продолжить старт и повторить её при следующем запуске.

#### Scenario: Сбой миграции
- **WHEN** при старте миграция завершается ошибкой
- **THEN** в логе есть предупреждение с именем миграции, в реестре её нет, сервер продолжает работу

#### Scenario: Повтор после исправления
- **WHEN** при следующем старте причина ошибки устранена
- **THEN** миграция выполняется и регистрируется

### Requirement: Выполненная миграция не повторяется
Миграция, уже записанная в реестре, SHALL пропускаться при последующих стартах.

#### Scenario: Повторный старт
- **WHEN** сервер перезапускается без изменений в БД
- **THEN** ни одна зарегистрированная миграция не выполняется повторно

### Requirement: Индексы схемы присутствуют на старых базах
После старта сервера на любой ранее созданной БД SHALL существовать все индексы, объявленные моделью товаров, включая индекс по (`store_code`, `last_scan_found`), и уникальный индекс магазинов по (`store_code`, `store_type`).

#### Scenario: Старая база без индекса
- **WHEN** сервер стартует на БД, где индекс `ix_product_last_scan` отсутствует
- **THEN** после старта индекс существует

#### Scenario: Дубликаты магазинов в старой базе
- **WHEN** в старой БД есть несколько магазинов с одинаковой парой (код, тип)
- **THEN** после старта остаётся самая ранняя запись, удаление остальных зафиксировано в логе, уникальный индекс создан
